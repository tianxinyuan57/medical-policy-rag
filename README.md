# 🏥 医疗政策 RAG 问答系统

![Python](https://img.shields.io/badge/Python-3.11-3776AB?logo=python&logoColor=white)

![Streamlit](https://img.shields.io/badge/Streamlit-FF4B4B?logo=streamlit&logoColor=white)

基于 **RAG（检索增强生成）** 架构的医疗政策智能问答系统。输入自然语言问题，从 94 部公开医疗法规及政策文件中检索相关条款，生成带引用溯源的准确回答。采用**条款感知智能切分**（按"第X条"/"一、二、三"结构切分），而非固定字数切分，语义边界精准对齐法律文档结构。

> ⚠️ 本项目**仅使用公开发布的法律法规文本**，不包含任何内部或非公开材料。

## ✨ 核心特性

- **混合检索**：BM25 关键词 + 向量语义双路召回，RRF 融合排序，Hit@5 达 100%（纯向量基线 90%）
- **引用图谱**：自动抽取 94 部法规间的 147 条引用关系，检索时沿引用边扩展召回关联法条（GraphRAG）
- **术语归一化**：口语→法规术语的领域词表（「突击检查」→「飞行检查」），检索命中率 0/5 → 5/5
- **引用校验**：逐条核验回答中的「《X法》第Y条」是否真在检索片段中，**可量化的防幻觉**
- **防幻觉**：Prompt 约束 + 拒答机制 + 事后引用核验三层防护
- **增量更新**：新增政策文件无需重建全库，一条命令增量入库
- **完整评估**：10 道测试题覆盖精确检索/理解推理/拒答测试，含调优实验记录

## 📐 技术架构

```
用户提问「医院被突击检查会查什么？」
  ↓
🔤 术语归一化：「突击检查」→ 飞行检查
  ↓
  ├──→ BM25 关键词检索（jieba 分词 + 领域词典）──→ Top-20
  └──→ 向量语义检索（bge-small-zh-v1.5）      ──→ Top-20
         ↓
  RRF 倒数排名融合 ──→ Top-K 片段
         ↓
🕸️ 引用图谱扩展：沿法条引用边补召关联法规
   （命中《麻醉药品条例》→ 自动补《处方管理办法》第十一条）
         ↓
  拼入 Prompt + 反幻觉约束
         ↓
  DeepSeek API 生成回答（带引用来源）
         ↓
🛡️ 引用校验：逐条核对「《X法》第Y条」是否真在检索片段中
```

离线建库流程：

```
data/*.txt 政策原文
  → ① LangChain 加载
  → ② Smart Splitter 智能切分（按条款/序号结构，非固定字数）
     ├─ A类（73部法律法规）：按"第X条"切分
     ├─ B类（19部通知/意见）：按"一、二、三"切分
     └─ C类（2部其他文档）：fallback 段落切分
     + 太短条款自动合并 + 太长条款二次切分
  → ③ bge-small-zh-v1.5 向量化
  → ④ 存入 Chroma 向量库
```

## 🛠️ 技术栈

| 组件 | 选型 | 说明 |
|------|------|------|
| LLM | DeepSeek API | OpenAI 兼容接口，性价比高 |
| Embedding | BAAI/bge-small-zh-v1.5 | 本地中文模型，512 维，离线可跑 |

| 关键词检索 | rank-bm25 + jieba | 中文分词含 50 个医疗政策领域词 |
| 融合排序 | RRF (k=60) | 倒数排名融合，免归一化免调权重 |
| 框架 | LangChain | 文档加载、切分、检索统一接口 |
| 语言 | Python 3.11 | conda 隔离环境 |

## 🚀 快速开始

### 1. 环境准备

```bash
# 创建 conda 环境
conda create -n medrag python=3.11 -y
conda activate medrag

# 安装依赖
pip install -r requirements.txt
```

### 2. 配置 API Key

```bash
cp .env.example .env
```

然后编辑 `.env`，填入你的 [DeepSeek API Key](https://platform.deepseek.com)。

### 3. 构建知识库

```bash
# 全量构建（首次）
python src/build_index.py --mode full

# 增量更新（新增文件后）
python src/build_index.py --mode update
```

### 4. 开始问答

```bash
# 交互式问答
python src/rag.py

# 带检索细节的调试模式
python src/rag.py --verbose

# 运行预设测试
python src/rag.py --test
```

### 5. 启动 Web 界面

```bash
streamlit run app.py
```

包含 5 个页面：对话问答（流式输出）、引用图谱（交互式力导向图）、
评估面板、知识库浏览、系统信息。

### 6. 运行评估与实验

```bash
# 10 道题的端到端评估
python src/evaluate.py

# 20 题检索策略对比实验（向量 vs BM25 vs 混合 vs 重排）
python src/retrieval_experiment.py

# 引用校验测试（含负向测试）
python src/citation_verifier.py

# 查询改写测试
python src/query_rewriter.py

# 引用图谱统计
python src/citation_graph.py --stats

# 查看某部法规的引用关系
python src/citation_graph.py --node 药品管理法

# 导出图谱可视化 HTML
python src/graph_viz.py
```

### 检索策略对比实验

独立的 20 题检索测试集（语义型 6 题 / 术语型 7 题 / 混合型 7 题），对比 4 种策略：

| 策略 | Hit@5 | MRR | P@5 | 延迟 |
|------|-------|-----|-----|------|
| A. 仅向量检索（基线） | 90% | 0.825 | 0.700 | 19ms |
| B. 仅 BM25 检索 | 85% | 0.785 | 0.570 | 3ms |
| **C. 混合检索（RRF）** ✅ | **100%** | **0.950** | **0.740** | **20ms** |
| D. 混合检索 + Cross-Encoder 重排 | 100% | 0.938 | 0.690 | 6159ms |

**分类型看，两种检索确实互补**（MRR）：

| 策略 | 语义型 | 术语型 | 混合型 |
|------|--------|--------|--------|
| 仅向量 | 0.833 | 0.714 | 0.929 |
| 仅 BM25 | 0.533 | **1.000** | 0.786 |
| 混合（RRF） | **1.000** | 0.929 | 0.929 |

- 语义型（"打疫苗要交钱吗"）→ BM25 惨败（0.533），向量占优
- 术语型（"DIP 病种分值付费"）→ BM25 完胜（1.000），向量吃力
- 融合后两类都拿到接近最优的成绩

**关键决策：为什么不用重排？**

Cross-Encoder 重排是 RAG 的常见"标配"，但实验显示在本场景下是**负收益**——MRR 从 0.950 降到 0.938，延迟从 20ms 涨到 6159ms（300 倍）。

根因分析（以"个人健康信息被泄露了怎么办？"为例）：重排模型被"**怎么办**"这个意图词带偏，把《举报处理办法》《互联网诊疗管理办法》排到前面，正确答案《个人信息保护法》从第 1 位掉到第 4 位。Cross-Encoder 对意图词过度敏感，稀释了核心实体"个人信息"的权重。

推测原因：本项目的 chunk 已是**条款级切分且带 `[《法名》第X条]` 标注**，语义边界本身很干净，两路检索的排名信号足够可靠，重排能补充的信息有限。

→ 默认关闭重排，但保留 `use_reranker` 开关便于换模型/换场景时重新验证。

## 🛡️ 引用校验：把「防幻觉」从口号变成指标

RAG 的标准防幻觉手段是在 Prompt 里写「只依据参考原文」。
但这只是**请求**模型别编，没有**验证**它有没有编。

本系统在生成后做事后核验：把回答里每一处「《X法》第Y条」抽出来，
回到检索片段里查证。

### 能抓出的四类幻觉

用故意构造的错误回答做负向测试，全部准确识别：

| 幻觉类型 | 示例 | 检出 | 诊断信息 |
|---------|------|------|---------|
| 条号编造 | 《药品管理法》第九百九十九条 | ✅ | 该法规在参考原文中，但未找到此条款 |
| 张冠李戴 | 用《护士条例》解释假药 | ✅ | 该法规不在本次参考原文中 |
| 虚构法规 | 《假药认定管理办法》 | ✅ | 该法规不在本次参考原文中 |
| 真假混合 | 一句真引用 + 一句假引用 | ✅ | 精确定位到假的那一处 |

### 两个必须处理的技术陷阱

**陷阱 1：metadata 只记录 chunk 的起始条款**

我们的 chunk 会合并短条款，所以标签是「第六十一条」的片段，
正文实际含第 61~75 条。只比对 metadata 会漏判大量正确引用
→ **必须扫描正文**。

**陷阱 2：正文里的条款号可能是「转引别的法规」**

《药品管理法实施条例》第 61 条写着「……依照《药品管理法》第八十条处罚」。
这个「第八十条」属于《药品管理法》，不属于本条例
→ **判据：条款号前紧跟「》」的是转引，不计入**。

### 置信度分级

模型常用简称（《条例》《管理规定》）。由于 `"条例" in "麻醉药品和精神药品管理条例"`
恒真，简称匹配存在误判风险，因此单独标记为 `abbrev` 置信度，与精确匹配区分。

## 🔤 术语归一化：用户说人话，法规说术语

对知识库做词频统计后发现的真实差距：

| 用户会说 | 法规实际用词 | 知识库出现次数 |
|---------|------------|--------------|
| 报销比例 | **支付比例** | 2 vs 18 |
| 异地看病 | **跨省异地就医** | 0 vs 299 |
| 医保定点药店 | **定点医药机构** | 0 vs 345 |
| 突击检查 | **飞行检查** | 0 vs 76 |

用户按自己的说法提问，BM25 关键词路几乎必然落空。

### 扩展式改写，而非替换式

```
✗ 替换：「异地看病能报销吗」→「跨省异地就医能支付吗」
  风险：丢失用户原意，向量检索反而变差

✓ 扩展：「异地看病能报销吗 跨省异地就医 直接结算 支付比例」
  好处：BM25 命中术语，向量检索保留原始语义
```

因为本项目是 BM25 + 向量混合检索，扩展式改写能让两路各取所需。

### 实测效果

| 问题 | 改写前 Top-5 命中 | 改写后 |
|------|------------------|--------|
| 医院被**突击检查**会查什么？ | 0/5 | **5/5** |
| **医闹**怎么处理？ | 1/5 | **4/5** |
| **跟师学医**的人能行医吗？ | 3/5 | **5/5** |
| **异地看病**能报多少？ | 2/5 | 3/5 |
| 打疫苗要花钱吗？ | 4/5 | 3/5 ⚠️ |

7 题中 4 题提升、2 题持平、1 题轻微下降（"免疫规划"引入了《传染病防治法》，
但《疫苗管理法》仍在 Top-1，不影响答案）。

「突击检查」那题是最典型的案例：改写前完全没找到《飞行检查管理暂行办法》，
因为这两个词**字面完全不同，向量也抓不住这个专业术语映射**。

### 两级策略

1. **词表改写**（默认）：60+ 组领域映射，零 LLM 成本，延迟 ~0ms
2. **LLM 兜底**（可选）：词表未命中时调用 LLM 补充术语，处理长尾表达

已经很专业的问题（如「医疗保障基金飞行检查的启动情形」）会跳过改写。

## 🕸️ 法条引用图谱

法规不是孤立文本，而是**相互引用的网络**。系统自动从原文抽取引用关系建图，
检索时沿引用边补充召回 —— 这是纯向量检索做不到的。

### 图谱规模

| 指标 | 数值 |
|------|------|
| 有引用关系的法规 | 69 / 94 部 |
| 唯一引用边 | 147 条 |
| 引用总数 | 267 处 |
| 依据关系（下位法→上位法） | 63 条 |

### 图谱自动发现了法律位阶结构

**被引用最多**（基础性法规）：

| 次数 | 法规 |
|------|------|
| 16 | 《医疗机构管理条例》 |
| 14 | 《药品管理法》 |
| 13 | 《医师法》 |
| 10 | 《医疗保障基金使用监督管理条例》 |

**引用他人最多**（综合性文件）：《关于加强首诊和转诊服务》11 部、
《医疗质量安全核心制度要点》10 部、《长期处方管理规范》9 部。

这个结果没有任何人工标注 —— 纯粹从文本里的「依据《XX》」「依照《XX》第X条」抽出来的。

### 图扩展实际效果

问「医疗机构使用麻醉药品有什么特殊要求？」：

| 来源 | 召回方式 |
|------|---------|
| 《麻醉药品和精神药品管理条例》第 36、39 条 | 混合检索 |
| 《医疗机构麻醉药品、第一类精神药品管理规定》第 3、14 条 | 混合检索 |
| **《处方管理办法》第十一条** | 🕸️ **图谱扩展** |

第十一条规定「执业医师经考核合格后取得麻醉药品处方权」—— 这是回答该问题的
关键条款，但它在《处方管理办法》里，字面上与「麻醉药品使用要求」距离较远，
纯向量检索排不进 Top-5。图谱通过「《麻醉药品条例》被引用于《处方管理办法》
第七十二、七十三条」这条边把它拉了进来。

### 工程细节

1. **名称归一化**：《中华人民共和国药品管理法（2019 年修订）》≡《药品管理法》；
   同时修复 PDF 断行造成的《处方 管理办法》
2. **噪音过滤**：《医疗机构执业许可证》是证照、《条例》是自指代词 —— 都不算引用
   （973 处书名号里过滤掉 393 处）
3. **关系分类**：按引用前的触发词区分「依据 / 参照 / 提及」三类
4. **扩展片段选择**：不能取关联法规的第一个片段（那是「前言/总则」，无实质内容），
   要在该法规的片段子集里按查询词做相关性排序，并对前言类降权

### 顺带发现的数据质量问题

建图过程中发现两个文件混入了其他文档的内容（早期批量拆分 MD 时的边界错误）：

- `疾病诊断相关分组DRG付费技术规范.txt` —— 93% 是别的文档（17726 → 1249 字）
- `医疗保障按病种付费管理暂行办法.txt` —— 尾部混入《医疗机构审批管理规定》

**这正是做图谱的意外收获**：引用关系出现异常（DRG 技术规范凭什么引用《药品管理法》18 次？）
反过来暴露了数据问题。已修复。

> ⚠️ **已知局限**：知识库中 25 个文件（27%）是条文节选而非全文，
> 例如《医师法》仅 1853 字。这些文件的引用关系抽取不完整。

### Top-K 调优记录

**问题**：跨文件对比题（"医师 vs 护士的紧急责任"）在 Top-K=3 时只检索到一方文件。

**排障过程**：
1. 先看检索结果 → 3 个片段全来自《护士条例》→ 定性为**检索问题**（非生成问题）
2. 将 Top-K 从 3 调至 5 → 检索同时覆盖《医师法》和《护士条例》
3. 回归测试 10 道题 → 全部通过，无副作用

**结论**：跨文件对比题需要更大的 K 值保证检索覆盖度。

## 🔑 面试要点速查

1. **RAG 七步链路**：加载 → 切分 → 向量化 → 存储（离线）→ 问题向量化 → 检索 Top-K → 拼 Prompt 生成（在线）
2. **Smart Chunking**：不满足默认 500 字切分 → 分析 94 部文档的结构特征 → 按"第X条"/"一、二、三"切分 → 太短合并 + 太长二次切分 → 每个 chunk 注入条款标签
3. **混合检索**：单路向量对专有名词（"飞行检查""DIP 分值"）命中率低 → 加 BM25 关键词路 → RRF 融合（只看排名不看分数，免归一化）→ Hit@5 90%→100%
4. **敢于做减法**：Cross-Encoder 重排是常见标配，但实验证明本场景负收益（延迟涨 300 倍、MRR 反降）→ 默认关闭。有数据支撑的技术选型 > 堆砌流行组件
5. **GraphRAG**：法规是引用网络 → 抽 147 条引用边建图 → 检索后沿边扩展召回 → 图谱自动重现了法律位阶结构（被引用最多的正是《医疗机构管理条例》《药品管理法》《医师法》）
6. **图谱的副产品**：引用关系异常反过来暴露了数据质量问题（DRG 技术规范凭什么引用《药品管理法》18 次？→ 查出文件混入了别的文档）
7. **可验证的防幻觉**：不止在 Prompt 里喊「别编」，而是事后逐条核验「《X法》第Y条」是否真在检索片段中 → 输出引用准确率这个硬指标
8. **术语归一化**：统计发现「报销比例」在法规里只出现 2 次而「支付比例」出现 18 次 → 建 60+ 组口语术语映射 → 「突击检查」类问题命中率 0/5→5/5
9. **防幻觉三板斧**：Prompt 约束"只用原文" + 给拒答退路 + 低 temperature
10. **引用溯源**：chunk 带 metadata + 条款标签 → Prompt 里标注来源 → 模型精确引用"根据《XX法》第X条"
11. **排障思路**：答案不对 → 先看检索 → 检索没找对改检索，检索找对了改 Prompt
12. **增量更新**：对比 Chroma 已有 source 和 data/ 目录，只处理新文件
